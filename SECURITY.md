# Security policy

Please report security issues through the repository's private security-advisory feature. Do not open a public issue containing a vulnerability, secret, personal information, or private service detail.

Reports should include the affected version, the smallest safe reproduction, the expected impact, and any suggested mitigation. Remove real records and credentials before submitting supporting material.

The maintainers will acknowledge a report, assess severity, coordinate a fix, and publish an advisory when appropriate.

The local public-safety check scans the working tree, Git index, and every reachable Git blob. Once the public repository is created, maintainers should also enable GitHub native secret scanning and push protection in the repository security settings.
